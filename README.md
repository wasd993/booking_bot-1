# 🤖 Telegram-бот для записи на приём — Пакет 1

> Telegram Stars · aiogram 3.x · SQLite · Python 3.11+

Полнофункциональный бот для управления записями на приём с поддержкой **нескольких специалистов**, системой **рефандов** (автовозврат Stars) и **быстрым конструктором расписания**.

---

## 🚀 Быстрый старт

### 1️⃣ Клонировать / распаковать проект

```bash
cd booking_bot
```

### 2️⃣ Создать виртуальное окружение

```bash
python3 -m venv venv
source venv/bin/activate        # Linux / macOS
# venv\Scripts\activate         # Windows
```

### 3️⃣ Установить зависимости

```bash
pip install -r requirements.txt
```

### 4️⃣ Настроить `.env`

```bash
cp .env.example .env
```

Откройте файл и заполните переменные:
- **`BOT_TOKEN`** — токен от [@BotFather](https://t.me/BotFather) (обязательно)
- **`ADMIN_IDS`** — ваш Telegram ID, цифры (узнать: [@userinfobot](https://t.me/userinfobot); несколько админов: `111,222,333`)
- **`STARS_PRICE`** — стоимость записи в Stars (целое число ≥ 1, пример: `10`)

### 5️⃣ Запустить бота

```bash
python main.py
```

Бот готов к использованию! Откройте Telegram, найдите своего бота и нажмите `/start`.

## ⭐ Telegram Stars — система оплаты и рефундов

### 💰 Как работает оплата

```
Клиент нажимает "📅 Записаться на приём"
        ↓
Выбирает специалиста → дату в календаре → время из доступных слотов
        ↓
Слот резервируется (статус: pending, таймаут 30 мин)
        ↓
Бот отправляет счёт (invoice) в Telegram с суммой STARS_PRICE
        ↓
Telegram показывает экран оплаты (нативно, без перенаправления)
        ↓
pre_checkout_query → бот проверяет слот ещё доступен → отвечает ok
        ↓
successful_payment → запись активируется (статус: active), сохраняется charge_id
```

### 🔄 Система рефундов (возврат Stars)

**Условия возврата:**
- ✅ Отмена была инициирована **более чем за 12 часов** до времени записи
- ✅ С момента оплаты прошло **менее 30 дней** (лимит Telegram)
- ✅ `charge_id` сохранён в БД

**Что происходит при отмене:**
- **Если 12+ часов:** 🤖 Бот автоматически возвращает Stars клиенту → запись отменяется ✅
- **Если < 12 часов:** ⚠️ Возврат невозможен, клиенту показывается контакт специалиста → "Пожалуйста, обратитесь к специалисту [Имя] для согласования отмены"

**Технические детали:**
- Валюта: `XTR` (внутренний код Telegram Stars)
- `provider_token=""` (пустая строка, обязательна для Stars)
- Возврат: `bot.refund_star_payment(user_id, charge_id)` (асинхронно)

### 📊 Статусы записей

| Статус | Значок | Описание |
|--------|--------|----------|
| **active** | ✅ | Оплачена, ожидает назначенного времени |
| **cancelled** | ❌ | Отменена клиентом или администратором |
| **pending** | ⏳ | Зарезервирована, ожидает оплаты (таймаут 30 мин) |

## 👥 Управление несколькими специалистами

Бот полностью поддерживает работу с несколькими специалистами:

### Для администратора
1. **Добавить специалиста:**
   - `/admin` → 🧑‍⚕️ **Специалисты** → ➕ **Добавить**
   - Введите ФИО и специальность
   - Специалист добавлен и автоматически становится активным (если это первый)

2. **Переключить активного специалиста:**
   - `/admin` → 🧑‍⚕️ **Специалисты** → кликните на нужного (появится ✅)
   - Все новые записи будут привязаны к активному специалисту

3. **Удалить специалиста:**
   - `/admin` → 🧑‍⚕️ **Специалисты** → 🗑️ рядом с именем
   - Если это был активный специалист, автоматически активируется следующий
   - Записи остаются в истории с именем специалиста

### Для клиента
- При записи видит имя **активного в момент записи** специалиста
- В личном кабинете "📋 Мои записи" видит, к кому была записана каждая встреча
- При отмене < 12 часов видит точный контакт того специалиста, у которого была запись

## 🌐 Деплой на хостинг

### VPS (Linux/Ubuntu с systemd)

**Установка:**
```bash
# 1. Клонировать проект на сервер
cd /opt && git clone <ваш-репо> booking_bot
cd booking_bot

# 2. Создать виртуальное окружение
python3 -m venv venv
source venv/bin/activate

# 3. Установить зависимости
pip install -r requirements.txt

# 4. Создать .env с переменными окружения
cp .env.example .env
# Отредактируйте .env с вашими значениями
```

**Создать systemd-сервис:**
```bash
sudo nano /etc/systemd/system/booking_bot.service
```

Содержимое файла:
```ini
[Unit]
Description=Telegram Booking Bot
After=network.target

[Service]
Type=simple
User=ubuntu                              # замените на ваш пользователь
WorkingDirectory=/opt/booking_bot
Environment="PATH=/opt/booking_bot/venv/bin"
EnvironmentFile=/opt/booking_bot/.env
ExecStart=/opt/booking_bot/venv/bin/python main.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

**Запустить:**
```bash
sudo systemctl daemon-reload
sudo systemctl enable booking_bot          # включить автозапуск
sudo systemctl start booking_bot           # запустить сейчас

# Просмотр логов:
sudo journalctl -u booking_bot -f
```

### Render / Railway / Heroku

**Шаг 1:** Загрузите переменные окружения в панель проекта:
- `BOT_TOKEN` — токен от BotFather
- `ADMIN_IDS` — ваш ID (или несколько через запятую)
- `STARS_PRICE` — цена в Stars

**Шаг 2:** Убедитесь, что в репозитории есть файл `Procfile`:
```
web: python main.py
```

**Шаг 3:** Залейте код и подождите деплоя — бот начнёт работать автоматически.

### Бэкапирование

Важно! База данных хранится в файле **`bot.db`** в корне проекта.

**Скачивать бэкап локально:**
```bash
# С вашего VPS
scp user@server:/opt/booking_bot/bot.db ~/backup_$(date +%Y%m%d).db

# Или встроить скрипт бэкапирования в systemd-таймер
```

**Восстановление:**
```bash
# Просто замените bot.db в проекте на сохранённую копию
cp ~/backup_20260101.db /opt/booking_bot/bot.db
```

## ❓ FAQ

**Q: Как добавить нескольких специалистов?**
```
A: /admin → 🧑‍⚕️ Специалисты → ➕ Добавить
   Введите ФИО и специальность каждого. Первый автоматически становится активным.
```

**Q: Клиент видит одного специалиста, но в системе несколько — почему?**
```
A: Показывается ИМЯ АКТИВНОГО специалиста (тот, у которого стоит ✅ в меню специалистов).
   Переключитесь на нужного: /admin → 🧑‍⚕️ Специалисты → клик на имя
```

**Q: Как работает возврат Stars?**
```
A: Автоматический возврат ТОЛЬКО если отмена за 12+ часов до записи.
   Если < 12 часов: клиент видит "Свяжитесь с [имя специалиста]"
   Возврат работает в течение 30 дней с момента оплаты.
```

**Q: Слот занят, но записи нет?**
```
A: Pending-запись старше 30 мин считается истёкшей и автоматически удаляется.
   Слот должен освободиться. Если нет — очистите вручную:
   /admin → 📅 Расписание → 🗑️ Удалить → выберите слот
```

**Q: Бот не отвечает на /start**
```
A: Проверьте:
   1. BOT_TOKEN в .env — правильный ли? (скопируйте из BotFather без пробелов)
   2. Не запущено ли два экземпляра бота одновременно
   3. Логи: sudo journalctl -u booking_bot -f (если на VPS)
```

**Q: Платёж проходит, но запись не подтверждается**
```
A: Убедитесь, что хэндлер payments.py включён ПЕРВЫМ в main.py:
   dp.include_routers(payments.router, admin.router, client.router)
   (если порядок неправильный, successful_payment не сработает)
```

**Q: Как скачать выписку по всем записям?**
```
A: /admin → 📤 Экспорт Excel
   Бот отправит .xlsx файл со всеми записями, отфильтрованными по дате.
   Можно открыть в Excel, Google Sheets, LibreOffice.
```

**Q: Где хранятся данные?**
```
A: В файле bot.db (SQLite) в корне проекта.
   Для бэкапа: скопируйте этот файл на безопасное место.
   Для восстановления: замените bot.db на сохранённую копию.
```

**Q: Как добавить несколько администраторов?**
```
A: В .env укажите ID через запятую без пробелов:
   ADMIN_IDS=123456789,987654321,555666777
```

**Q: Специалист удалён, но записи остались — где они?**
```
A: Записи сохраняются с именем специалиста (specialist_name).
   /admin → 📋 Записи сегодня или 📤 Экспорт Excel — увидите все записи.
   Данные не теряются.
```

**Q: Можно ли использовать без Telegram Stars?**
```
A: Текущая версия требует Stars для оплаты (вбита в логику).
   Для других способов оплаты нужна переделка системы платежей.
```

**Q: Как изменить цену записи?**
```
A: Измените STARS_PRICE в .env на нужное число.
   Перезагрузите бота (systemctl restart booking_bot).
   Новая цена применится ко всем новым записям.
```
